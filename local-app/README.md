# 本机 Docker 运行（第一阶段）

Docker Desktop 中的项目名为 `chaxun`，继续使用原有的 `local-app_phone_mysql` 数据卷。首次安装且配置文件和数据卷均不存在时，启动脚本会创建新卷；若只缺其中之一，脚本会停止并要求找回原配置或恢复数据，避免误用空库。迁移到新电脑时，请按备份恢复流程准备原配置及数据卷。

先启动 Docker Desktop，在 PowerShell 执行：

```powershell
cd "C:\Users\34861\Documents\ChatGPT\手机信息查询工具\local-app"
powershell -ExecutionPolicy Bypass -File .\启动项目.ps1
```

首次启动生成本地 `.env`，请妥善保存，密码丢失后不能仅靠重新生成文件访问已有数据库。访问 http://localhost:61434 。同一局域网手机可访问电脑局域网 IP 的 61434 端口（需防火墙允许）。

首次启动需要下载容器镜像和 Python 依赖。如果出现 `auth.docker.io` 的 EOF 或 TLS 超时，请先确认 Docker Desktop 能连接镜像仓库，再重新运行启动脚本。启动失败时不要删除 `.env` 或数据库卷。

搜索框的拍照按钮已加入背面相似图试用：用户选择的图片只在浏览器内处理，页面从本机服务读取参考图后比较；只对画面非常接近的图片提供候选，并非可靠的实拍机型识别。当前仅有 HUAWEI Pura X Max 中国大陆零度白 1 张折叠态背面参考图，实拍角度、背景或光线变化可能无法匹配；候选需人工确认。未匹配时仍尝试浏览器支持的型号文字识别，否则应手动搜索。参考清单位于 `back-references.json`，文件与记录的 SHA-256 不一致或机型不匹配时不会参与匹配；添加样本前须逐张核验机型、配色、地区、图片和来源。这个试用功能尚未解决通用手机背面识别。

本地比较允许有限的整体亮度变化；同一型号有多张符合条件的参考图时只展示最相近的一项。相似程度只作候选排序，不能证明型号正确，也尚未完成不同光线、角度和手机壳的实拍准确率评估。

在线相似图片搜索采用可选的 Google Cloud Vision Web Detection，默认关闭，不影响本地相似图比较。当前尚未配置账号或密钥，也未经真实云端验证。日后如需启用，请在 `local-app/.env` 中设置 `ONLINE_VISION_ENABLED=1` 和 `GOOGLE_VISION_API_KEY=自己的密钥`，并重建后端；需自行开通服务并确认网络、费用及地区可用性。每次在线搜索会先提示确认，随后将旋转后的选中区域（未框选时为整张照片）缩放并转换为 JPEG 发送至 Google；本应用不保存上传图片，返回网页仅作候选，不自动更改机型数据。每分钟最多发起 6 次在线请求（单进程本机限制），不能代替供应商配额或费用限制；请妥善限制 API 密钥。无需在线功能时保持关闭。

背面框选页面可选择整张图片，也可拖动选框；选框获得焦点后，方向键移动，Shift 加方向键调整宽高，Alt 可加大步长。旋转照片会清除选框。选整张图并不能保证识别成功，复杂背景仍建议手动框选。

管理面板的“背面识图参考库”可登记额外样本：先把图片放入项目 `images/` 目录，输入已发布机型 ID 和 `images/文件名`，检查并预览；填写配色、地区、来源、可信状态和核对日期，并逐项确认后加入。只支持本地 PNG、JPEG、WebP；相同文件不会重复登记。登记记录可停用或在文件未变化时重新启用，文件或机型变化会自动排除。该入口管理新增记录，内置清单仍单独管理。新增记录保存在数据库，图片文件仍在 `images/`，两者都要备份。

数据库响应较慢时，如果已经开始操作，页面会保留当前输入；数据载入后切换页面即可显示数据库中的最新内容。

首次启动会将项目根目录 index.html 中的机型数据按原样导入 MySQL；仅当数据表为空时导入，不覆盖已有数据。后续编辑原型不会自动同步到数据库；已有机型可在管理面板逐字段维护，新增机型可先预览再按说明增量导入。图片仍使用原型内地址，已有外链仍依赖网络。新反馈先保存在当前浏览器，再尝试提交数据库；提交未确认时可在反馈列表手动重试，同一条新反馈使用固定编号防止重复入库。旧版已保存反馈没有编号，提交状态未知，不会自动上传。浏览器数据清除后本地记录可能丢失。

首次导入前可双击 `比较新旧原型.bat`，对比当前原型和 `旧版查询工具.html` 并生成 `storage/原型机型差异.json`。报告不修改数据；旧版独有机型可能缺失近期核实内容，需要人工确认后再迁移。

管理面板的“旧版待核机型”从旧版原型中列出当前数据库没有的机型及其旧资料。点击“加入待审核”会将旧版完整记录复制到独立待审核表，不会发布给用户或视为已验证；遇到相同 ID 或名称会拒绝加入。在“待审核机型”中查看或搜索已加入的草稿，可看到待核、冲突和缺失数量；点击机型可直接进入字段编辑，也可输入机型 ID 读取。可逐项记录参数和来源、查看修改历史，并运行发布检查。发布要求非缺失字段具有明确核实状态、来源、地区和日期；缺失字段允许保留。发布时会隐藏旧主图和旧价格，并剔除未核实的发布日期；草稿原始记录保留。已发布旧机型的主图在管理面板完成五项人工验收并保存为“已核实”后，刷新用户页面即可显示；图片地址或本地文件内容变化、文件缺失或验收状态改变后会重新隐藏。外链在地址不变时内容仍可能改变，需要定期复查。按 ID/名称比较不能替代人工逐款核对。

容器运行后，可双击 `对账数据.bat`，只读比较当前原型与数据库的机型数量、独有机型和变化字段，不会修改或同步数据。报告只列字段名称，不列字段值；来源和核查元数据也会参与比较。此工具尚未在真实 Docker 数据库上验证。

`预览新增机型.bat` 只列出原型中有而数据库没有的机型，不会修改数据。确认备份及预览后，可在本目录执行 `docker compose exec -T backend python sync_seed.py --apply` 插入这些新机型；已有 ID 一律不覆盖，更新和删除须另行处理。该工具尚未在真实 MySQL 上验证。

`查看数据库缺口.bat` 只读输出数据库内 11 项字段的保守统计及未完成机型，区分缺失、待核实和资料冲突。字段填写了但缺来源、地区或核查日期时仍记作待核实；统计规则与旧清单不完全相同，数量不能直接混比。此工具尚未在真实 MySQL 上验证。

定时容器每轮结束后等待 3 分钟，生成 `storage/reports/最新缺口报告.json`，报告包含 UTC 生成时间；任务使用数据库锁避免重复运行。它会统计现有数据，并可低频检查已登记的厂商官网线索；**不会自动确认或补充参数**。任务失败会记录在 `docker compose logs scheduler` 并在下一轮重试。管理面板的“定时盘点状态”可查看最近报告时间与统计，超过十分钟未更新会提醒检查任务；此提醒不等于确认任务失败。报告只覆盖已发布数据库机型，统计口径不同于原型清单。

`查看用户反馈.bat` 在容器运行后只读显示数据库中最近 100 条反馈，反馈可能包含个人信息，请勿随意分享窗口内容；该功能不是管理后台，不支持修改或删除，尚未在真实 MySQL 上验证。

管理面板的“最近反馈”可单独刷新、按待处理等状态筛选并保存状态；每次最多加载 100 条，点击“加载更早反馈”继续查看历史。筛选和计数仅针对已加载的记录，不代表全部历史反馈。

本机管理面板地址为 http://localhost:61435 ，需要输入 `.env` 文件中的 `ADMIN_TOKEN`。启动脚本会为旧配置补生成口令。该端口仅绑定本机；面板可查看缺口与最近反馈、标记反馈处理状态，并可按机型 ID 编辑单项字段和查看修改历史，要求来源、地区和核对日期，修改前后写入数据库日志。编辑前建议备份。口令请勿分享；如果要更换，应修改 `.env` 中的值并重建后端容器。

读取已发布机型或待审核草稿后，可在“发布日期”单独填写已核实的具体发布日期、来源网址、地区版本、核对日期及可信状态。保存时核对读取后的原日期和来源是否变化，并记录修改历史；草稿发布时保留已核实的日期。此处不代表上市日期，也不会自动联网核实。

管理面板的“发布日期缺口”单独盘点日期、标签和来源元数据，并可按机型搜索；开售、上架等其他日期会列为发布日期待核实。保存新发布日期时，原日期标签和值保存在修改历史中，当前详情改为展示发布日期。盘点不会重新验证来源网页中的内容。

发布日期缺口支持组合机型名称和缺口状态筛选，并显示符合条件的机型数；筛选只影响当前列表，不改变核查状态或机型资料。

盘点发布日期后可将当前筛选导出为 CSV，包含现有日期标签、缺口状态和最近一条查找记录；导出不包含全部历史记录，也不表示日期已核实。文件采用 UTF-8 BOM 并对公式前缀作文本保护。

发布日期清单和导出还分别显示当前日期已登记的来源、冲突来源、地区、核对日期及可信状态；这些是原有证据记录，不代表此次重新访问或确认来源。

已盘点发布日期后，保存已发布机型的发布日期会自动刷新清单；若刷新失败，保存结果仍保留，可重新盘点。保存期间继续编辑表单时，后续输入会保留。

发布日期保存发生网络中断时，页面会提示保存结果未知；请重新读取该机型并检查后再重试，避免误判。保存期间清除或更换管理口令后，旧响应不会更新当前提示或重新加载清单。

读取已发布机型后可维护“销售状态”，需填写地区版本、核查渠道、来源及日期；修改记录会保存，详情页显示所填范围和来源。标记停售会在查询详情隐藏价格，但保留数据库里的历史价格。单个渠道缺货不能直接认定机型停售；状态不会自动联网更新，实际购买时请重新核查。

“历史版本价格”支持给已发布机型追加已核实的历史发布价或历史官方建议零售价，需填写地区、具体版本、币种、来源和核对日期；不提供实时渠道价格。保存前会检查读取时的价格记录是否发生变化，相同地区及版本不重复添加，原有数据不会覆盖。可选择已有价格逐条编辑；保存时重新填写核实状态及所需来源，保留其他版本和修改历史，并检查重复与并发变更。价格资料冲突时须先人工核查。停售机型仍不展示价格。

“历史价格盘点”按机型统计已登记价格条数，并标出价格记录缺失、来源待核和资料冲突，可按机型及记录情况筛选后进入维护。只有一条记录不代表该机型只存在一个版本；盘点不联网，不确认现售价格或已登记数据的真实性。

字段编辑区的“字段查找记录”可为已发布或待审核机型的指定字段记录地区版本、查找范围、日期及可选来源；无记录仅表示尚未在此功能中登记，并不证明从未查找。“本次未找到公开资料”只适用于记录的查找范围，不代表全网无资料。查找记录独立保存，不自动改变参数、可信状态或缺口统计；历史清单不会自动导入。

查找字段也可选择“发布日期”或“历史价格”，对应盘点列表会显示最近一条查找记录。历史价格的查找记录按机型归集，具体存储版本及地区请填写在查找范围中；它不代表该机型全部版本都已查找。

字段缺口加载后可导出当前筛选结果为 CSV，每行一个未完成字段，含最新查找情况及来源；该导出不包含其他历史查找记录或已完成字段。保存已发布机型的字段后会自动刷新字段缺口；也可点击“刷新字段缺口”。刷新失败不影响已成功的保存，请手动重试。“字段缺口”中可点击具体字段，直接读取对应已发布机型并定位到字段编辑和查找记录；点击本身不会修改数据。“字段缺口”分别显示已有字段来源记录及每个未完成字段最近一条查找记录；记录标注与当前盘点状态分开展示，并可按查找情况筛选；同时可组合机型名称、字段和核实状态。已发布机型的查找记录会显示在此清单，待审核机型的记录仍在字段编辑区查看。旧版草稿发布后，发布前的查找记录会自动出现在该机型的字段历史与缺口清单中，并标注“发布前”；发布后应在已发布机型中继续记录。

管理面板的“主图盘点”只检查原型主图索引中的本地文件是否存在，并标出内容相同的候选；不会访问外链，也不会判断画面、型号、配色、授权或其他图片。未验收的图片不得视为已核实。

在管理面板盘点后可输入机型 ID 打开主图，手动填写配色、地区、来源和日期并保存核查记录。标为已核实前需确认型号、配色、完整机身、无水印及促销内容、图片加载；记录保存在数据库。地址或本地文件内容变化会提示重新核实；外链内容可能在地址不变时发生变化，仍需定期人工检查。此功能仅覆盖原型主图，并不替代其他配色图片的逐张验收。

每次打开主图都需要重新确认实际加载：只有预览图加载成功后，“实际加载正常”才能勾选；加载失败或更换机型会清除该确认。图片能加载不代表型号、配色或画面合格。

也可双击 `启动项目.bat`。停止：`docker compose down`。不要加 `-v`，以免删除数据库卷。

数据库运行时可双击 `备份数据库.bat`，导出到 `storage/backups/`。可双击 `验证数据库备份.bat`，将最新备份恢复到不联网、不映射端口的临时 MySQL，检查当前应用所需数据表并显示各表记录数；较旧备份可能缺少后来新增的数据表，检查会列出缺失表；不会修改当前数据库。新备份会生成同名 `.sql.sha256` 摘要文件，验证时检查是否被修改；旧备份无摘要时会明确提示。复制备份时请同时复制 SQL 和摘要文件。记录数仅反映备份本身，不能证明与当前数据库完全一致。备份不含图片，须另外复制项目根目录 `images/` 和新增图片，并将这些文件复制到其他磁盘。目前没有向当前数据库自动恢复的脚本；实际恢复前应先备份当前数据库。

双击 `备份本地图片.bat` 可将项目根目录 `images/` 中的文件保存为独立 ZIP，并记录每个文件的 SHA-256；双击 `验证本地图片备份.bat` 可检查最新 ZIP 的完整性，不会解压或修改原图。该备份不包含数据库或远程图片，也不判断图片的型号、画面与来源是否正确。请同时备份数据库，并将两份备份复制到其他磁盘。

图片备份验证还会比较当前 `images/` 与备份的路径和 SHA-256，分别报告新增、当前缺少及内容变化的文件，每类最多显示前 10 个名称。无法读取当前目录时会单独提示；检查期间文件变化可能影响结果。

数据库备份验证还会只读比较隔离恢复的备份与当前 `chaxun` 数据库各表的记录数量，并列出数量不同的表。数量相同不能证明记录内容相同；对比时数据库也可能继续发生变化。当前数据库不可访问时，仍会报告备份恢复结果并提示比较未完成。

验证还会使用 MySQL 的 `CHECKSUM TABLE` 比较各表内容校验值，列出校验值不同的表；表不支持校验或读取失败时提示未完成。校验值不是逐条比较或加密证明，数据库在检查期间变化也可能产生差异；图片和远程资源不包含在检查中。

本系统面向本机或可信局域网。61434 对局域网可见，不提供 TLS 或公开部署防护，不应直接暴露公网。

需要复测反馈去重时，可在 `local-app` 目录运行 `docker compose -p phoneguide-concurrency-check -f tests/mysql_concurrency.yml up --abort-on-container-exit --exit-code-from verify`；测试使用无端口映射的隔离网络和临时 MySQL 数据，结束后运行同样的前缀加 `down` 清理测试容器与网络，不连接项目数据库。

官网线索检查：管理后台读取已发布机型后，可按字段检查已登记的受支持厂商 HTTPS 规格页。服务只读取有限的页面文字并提取关键词，仅允许同一官网域名内最多两次 HTTPS 跳转，不会自动确认或修改参数；动态加载、跳转或未列入白名单的页面需要人工查看。检查结果只供核对，不能证明版本、地区或字段正确。

电池、充电、重量和防护字段的线索优先展示包含常见数值单位的摘录，避免只展示页面导航中首次出现的关键词；单位可能来自相邻内容，也可能漏掉其他写法，仍须人工确认。

定时检查在电池摘录明确标注单一典型容量时，可展示“待核实”候选；存在多个容量或字段资料冲突时不生成候选。候选只保存在官网检查报告，不写入机型参数，需人工核对型号、地区、版本和原文后维护；旧检查结果不会自动补算。

实时价格：尚未接入可靠的渠道报价接口，现有价格属于标注来源的历史参考价，不代表当前成交价。不能将本功能视作实时价格或自动核实。

用户端“商城”展示符合条件的渠道报价快照，可按机型搜索、查看详情并打开所登记的 HTTPS 渠道页面。商品仅来自明确在售、地区和渠道匹配且未满 24 小时的手工核查快照；没有符合条件的记录时显示空状态。历史发布价不会当作在售价格，价格与库存以渠道页面为准；此功能不提供站内下单或支付。

商城也可展示已核对型号的官方商品页链接，无需假定当前有货或记录价格；明确停售机型不展示。当前接入 Xiaomi 17 Ultra 中国大陆小米商城商品页，核对日期 2026-11-21，链接和机型保存在首页的 `mallProductLinks` 中；实际版本、价格及库存请到渠道页面确认。

商城另接入 REDMI K100 中国大陆小米商城商品页，核对日期 2026-11-21；商城搜索后进入详情，返回时保留搜索词。

字段缺口支持按当前筛选结果选择起始项，逐项批量检查最多 5 个字段的已登记官网线索；可停止后续请求。检查只展示本轮结果，不保存查找记录、不更新字段或状态。已发出的请求不能撤回；筛选变化后起始项需重新按当前列表选择。未获取线索不代表资料不存在。

批量官网检查完成后，可选择成功的某项预填到该机型的字段查找记录。预填只标记“查找中”，需要自行确认地区版本、修改范围并手动保存；已有表单内容不会被覆盖，提取失败的项目不能用此入口生成记录。此记录不会修改参数或将字段标为已核实。

保存字段查找记录后，已发布机型的缺口清单会尝试刷新。提交后若表单和所选机型未变化，表单自动清空；提交过程中修改的内容会保留。网络中断时保存结果可能未知，请先查看当前字段记录，避免重复提交；手动清空表单不会删除已保存记录。

后台读取机型时，如果切换已发布与待审核记录、更改机型 ID 或清除口令，较早的读取结果不会覆盖当前选择。

批量官网线索检查支持导出本批 CSV，含字段、检查结果、来源、UTC 检查时间、片段或失败原因；导出不等于保存查找记录或核实字段。中途停止保留已完成项，可继续导出或填写查找记录；正在进行的请求结果不会计入。开始新批次或清除口令会清空本批页面结果，请先导出需要保留的内容。

定时官网线索检查默认开启（`AUTO_OFFICIAL_CHECK=1`）；不需要时在 `.env` 中设置 `AUTO_OFFICIAL_CHECK=0` 并重建 scheduler。只对已有受支持官网来源的缺失、待核或冲突字段检查，每次最多读取一款机型的一个官网页面，可分别检查该页面对应的多个未完成字段，至少间隔 30 分钟；同一机型字段及来源检查成功后 7 天内不重复检查；网络或服务器异常、检查中断至少等待 6 小时，页面 404/410 至少等待 30 天，其他失败至少等待 7 天。检查结果及失败情况保存在 `storage/reports/官网线索自动检查.json`，管理后台可按机型、字段和结果筛选，并分批查看较早记录。它只提取页面文字，不能确认型号、版本、地区、参数或图片，也不会自动修改数据库；需人工核对后另行保存。网页动态加载、跨域跳转或网络异常可能导致无片段或失败。报告记录最近 4000 次检查；若文件格式损坏会停止检查，不会覆盖原文件。

管理后台查看自动官网线索后，可选择成功检查的记录预填字段查找表单；需要自行填写地区版本并确认后保存。失败或中断的检查也可预填“查找中”记录，保存前需填写地区并人工确认；不会标成查无公开资料。原始检查结果可能过时，仍需核对当前型号、来源和字段。

官网检查支持同一受支持官网域名内最多两次 HTTPS 跳转；每次跳转重新验证地址和 DNS，并保留原始及跳转后的来源。跨域、非 HTTPS 和超出次数的跳转会停止，仍需人工确认来源及型号。

定时任务会将同一机型、同一原始官网地址的未完成字段合并为一次页面请求，并分别记录每个字段的线索或失败；不会跨机型合并，也不会重复检查冷却期内的字段。

在线搜图使用当前旋转方向与有效选区；没有有效选区时使用整张照片。发送前的确认提示会说明范围。此功能仍需自行配置服务账号、密钥并验证，不保证识别准确。

本地背面相似图比较会区分参考库为空、参考图加载或处理失败、以及已加载但未找到相似图；部分参考图失败时会提示结果可能不完整。参考图是否正确仍需人工验收，不保证实拍识别。

拍照识图入口可选择拍摄或从相册选择图片（具体相机和文件选择界面由浏览器决定）。本地参考图出现候选后，还可使用同一张图片重新框选或选择在线搜索，无需重新选图。在线搜索仍需配置并在发送前确认。

管理后台可手工登记已发布机型的多条渠道报价快照（需实际核查时间、版本、地区、渠道及 HTTPS 来源）。同一机型可按版本、地区与渠道登记多条报价（最多 20 条），重复组合需编辑原记录；修改前后值保留在历史中，并发变更会拒绝覆盖。查询页仅在机型销售状态明确为“在售”、报价地区与渠道和销售状态记录一致，且快照未满 24 小时时展示，并标明非实时和采集时间；停售、状态不明、未来或过期的快照不展示。未接入任何实时渠道接口，手工报价不代表当前售价或库存。

管理后台的“渠道报价盘点”会按未录入、可展示、已过期、停售隐藏、销售状态待核实、地区或渠道不匹配、记录无效分类，并可按机型和状态筛选进入维护。多条报价时，机型状态表示至少一条可展示或最优先的隐藏原因，逐条状态保留在接口中。未录入总数包含停售机型，和展示状态是不同口径；盘点只检查数据库快照，不代表渠道当前价格或库存。已加载盘点后保存报价会尝试刷新清单。

多条渠道快照在详情页默认只显示第一条，可展开查看其余版本；每条按自己的采集时间过期。旧版单条渠道快照仍可查看及编辑，新旧报价均不会自动补充，仍非实时成交价。

自动官网检查记录每次读取 50 条，可继续加载更早结果；按机型、字段或结果筛选时请重新点击查看。若后台记录被轮转，旧分页位置可能失效，需要重新读取。报告仍最多保留 4000 条，不能替代备份。

定时官网检查会保存提取文字的 SHA-256 摘要，并与同一机型、同一原始来源的上次有效结果比较，记录首次检查、文字变化、未变化、最终地址变化或未提取到文字。旧记录没有摘要时视为首次可比较检查；网页动态内容或版式文字变化也可能触发差异，未变化也不能证明参数正确。报告不保存完整网页，只保存原有的字段片段及摘要。

定时官网核查也会对比同一机型、字段和来源最近一次成功提取的字段摘录，并标记首次提取、未变化、有变化、未提取或页面地址变化；后台可按这些状态筛选。旧记录没有比较标记时显示“未记录字段比较”。对比的是关键词周围的摘录，广告、版式及动态内容也可能影响结果，摘录变化不等于参数变化，仍须核对型号、地区与来源。

新的定时检查结果可同时查看当前与上次成功提取的同字段摘录及来源地址，辅助人工比较；旧记录没有留存上次摘录时不会补造。后台提供 HTTPS 来源链接，链接目标由记录给出，仍须核对厂商、地区和型号。

在字段编辑区检查官网后，可选择一段提取原文填入字段编辑框；该内容包含上下文，不是自动核实的参数。填入时状态设为“待核实”，清空地区与核对日期，需人工核对、删改并填写后才可保存。未保存的编辑及“资料冲突”字段不会被此操作覆盖。

查询详情的每个参数可展开查看逐字段的记录状态、地区、核对日期和有效来源链接。状态按已登记资料及基本完整性显示，不代表本次自动重新核验；没有逐字段来源的已填写内容显示“待核实”，冲突与缺失单独标识。

字段详情与后台缺口统计使用相同的基本来源完整性规则：HTTP(S) 来源地址有效、地区不为空、核对日期为有效且不晚于北京时间当天的日期。仅根据这些条件和已登记状态展示，仍不代表重新访问来源验证。后台核对日期也按北京时间判断，以免 Docker 使用 UTC 时跨日误判。详情中若电池只找到额定值而典型值未确认，会对典型值显示更保守的待核实；开售日期不等同发布日期。

自动官网检查记录会区分页面不存在、访问受限、限流、服务器异常、网络故障和不支持的跳转；失败只说明本次访问结果，不代表该机型无公开资料。报告显示最早重试时间，实际时间还受 30 分钟全局间隔和其他待处理字段影响；旧失败记录按 7 天处理。
